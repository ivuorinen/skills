# Two chore(deps)! commits carry an unwarranted breaking marker that will spuriously major-bump to 3.0.0

## Problem

Two dependency-bump commits are marked breaking (`!`) despite touching only CI/tooling config, contradicting the repo's own commit-types.md, and will drive release-please to a spurious major version bump.

## Evidence

`8f1c411 chore(deps)!: update astral-sh/setup-uv action` — diff is `.github/workflows/validate-skills.yml | 2 +-` only. `b394d25 chore(deps)!: update pre-commit hook pre-commit/pre-commit-hooks` — diff is `.pre-commit-config.yaml | 2 +-` only. Neither touches any path under `skills/`. commit-types.md: "A workflow-only or CI-only dependency bump is never breaking... Strip the `!` from any dependency-bot commit that touches only `.github/`."

## Impact

.release-please-manifest.json is at "2.0.0" with the Release PR unmerged, so the next release evaluates both commits. release-please treats `!` as breaking regardless of the chore type, so the pending release major-bumps to 3.0.0 off two no-op CI dep bumps — misrepresenting semver to every consumer that pins this repo.

## Fix

Before the next Release PR merges, override the computed bump (Release-As directive / manual manifest correction) so the two `!` markers do not force 3.0.0, and correct the CHANGELOG classification. Prevent recurrence by stripping `!` from dependency-bot commits touching only `.github/` or tooling config in review, as commit-types.md already prescribes.
