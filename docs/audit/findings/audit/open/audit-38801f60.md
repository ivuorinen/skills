# post-bash-revalidate never validates eval sets after a Bash edit

## Problem

The GATES tuple has no entry for `scripts/validate-evals.py`, and `validate-evals-hook.py` fires only on Write and Edit. An eval set changed through Bash marks `skills/` as governed and is still never validated in-session.

## Evidence

```python
GATES = (
    ("scripts/validate-skill.py", [...]),
    ("scripts/validate-rules.py", [...]),
    ("scripts/check-version-sync.py", [...]),
    ("scripts/check-stdlib-only.py", [...]),
    (FINDINGS, ["python3", FINDINGS, "validate"]),
    (FINDINGS, ["python3", FINDINGS, "index"]),
)
```

Scenario: `sed -i 's/"assertions"/"asserts"/' skills/nitpicker/evals/evals.json` runs all six gates, none of which reads eval sets, and the malformed set passes until CI.

## Impact

Bash-mediated eval edits skip the in-session gate the hook exists to provide.

## Fix

Add `("scripts/validate-evals.py", ["uv", "run", "--quiet", "scripts/validate-evals.py"])` to GATES. Owner-only surface.
